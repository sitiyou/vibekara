# 偏好与模板收藏

## 本地偏好

长期偏好保存在 `$XDG_CONFIG_HOME/vibekara/preferences.md`，默认位于 `~/.config/vibekara/preferences.md`。用简短的 Markdown 条目保存本机媒体库、存储访问习惯、样式偏好、工具路径与投稿惯例。只对当前歌曲生效的要求写入该曲的制作记录。访问凭据由各工具自己的登录机制管理。

这个文件属于当前用户，可以直接打开阅读。将本机路径和账号约定留在配置目录，向外分享时只记录公开来源与产物。

`preferences.md` 上限为 **4096 个 UTF-8 字节**，包括标题、换行和收藏索引。收藏的模板源码、资源和选值另存于配置目录的 `templates/` 中。通过评审页管理收藏时，网页会维护对应的 Markdown 链接。

脚本化读取会返回偏好正文、收藏列表和内容摘要。保存编辑后的文件时，给脚本传入 `--write FILE --digest DIGEST`，其中 `DIGEST` 是读取时返回的摘要。遇到并发修改时重新读取并合并。遇到超限时精简重复或已撤销的条目。[preferences.py](../kara-previwer/scripts/preferences.py)

## 查找本机工具

先核对本次工程指定的路径，再查本地 `preferences.md`。可在文件的「工具」一节记录长期使用的可执行文件、源码目录、Python 解释器和单独配置的模型目录。比如 `pymss` 装在源码 checkout 的虚拟环境里时，记录 `~/src/pymss/.venv/bin/pymss`，下次直接调用。

路径未指定时，用 `command -v 工具名` 查 `PATH`，用 `uv tool list` 查 `uv` 安装的工具。源码安装再查已知项目的 `.venv/bin/`。Python 库用构建实际选定的解释器验证导入和所需接口。`pymss` 模型复用已有缓存，使用自定义模型目录时沿用已记录的 `PYMSS_MODEL_DIR`。只有这些位置都没有可用版本时，才安装当前阶段缺少的依赖。

### 验证字幕编译环境

从歌曲目录用实际编译解释器试读 `.nto`，再生成一个短 Hook。若工程依赖开发版，检查 `namioto.__file__` 与 `kara_templater.__file__` 是否指向预期安装或源码。评审服务启动、方案发布和快照重建都要使用同样的环境。通过 `PYTHONPATH` 加载开发版时，记录源码目录并在这些入口沿用。

## 模板收藏

在评审页的「我的模板」中保存当前模板和选值。制作下一首歌时，从收藏中选取模板，在新歌的歌词和音轨上预览。收藏需要可重建的模板源码。
