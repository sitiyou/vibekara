# 制作第一版卡拉 OK 评审

第一版的目标是选定整曲的视觉方向。让用户在同一段歌和画面上比较完整设计。选定方向后，再细调字号、字边、颜色、动作幅度或导唱符。

## 从曲目出发

先确定歌词的语气和断句、节奏或编曲的变化、画面构图和剪辑。选能看出这些差异的实际片段，包含首次或分段入唱、长音、换行和密集注音。整曲可拖动时，把起播点放在代表性入场之前。

字幕沿用默认的双行左右交替布局。用户主动要求时再改布局。字幕需要在明暗画面和快速歌词上都好读。音符时长、词边界和注音读法沿用核对过的打轴。入场与离场优先发生在可读的预留时间内，段首导唱符以该处的节奏为准。

## 做出真正不同的完整方案

先查实际渲染版本的效果目录，再挑适合本曲的几种主要机制。平稳扫色、跟随重拍、整音换色、光影显隐和字形聚散可以形成不同的方向。用字体、字宽、描边和色彩加强各自的表达。把同一机制下的换色、换字体或强度变化留作该方向的细调。每套用一句话指出最明显的差异，给出能直接比较的时间点。

从适合本曲的方向中挑首屏预设，保留一套克制、易读的参照。派生方案共用同一份打轴、录音、画面和起始位置。可共用构建逻辑的组合放在 `presets`。需要不同构建逻辑时，用 `alternatives`。

## 选择导唱符

有明确的段首引导需求时，为正文配一套导唱符。匹配正文的字体或笔形、字边、待唱色和高亮色。在同一帧里核对比例和对比度。备选要改变用户读拍的方式，例如连续扫过一组拍点，或逐拍读出数字。逐拍亮灭、整拍换色和连续扫色用各自准确的名称。承诺扫色时，检查一拍中途能同时看到扫前和扫后两侧。核对最后一拍与入唱的衔接。

## 组织评审控件

首屏放完整方案和影响方向的少量选项。用户选定方向后，按反馈开放相关细调。需要对比单项动效时，从效果目录选能在本曲片段中分辨的候选，覆盖明显不同的机制。每个候选都应提供一个清楚的选择理由。字体先核对本机实装和本曲字形。说明会影响这次比较的兼容性限制。

## 发布前验证

用实际画面检查每套首屏方案的入唱、换行、长音和退场，从曲中再抽查最长一句和颜色最难读的画面。验证几个方向在相同片段里确实可区分，并且都能重建整曲。把浏览器链接、推荐时间点和各套的主要差别交给用户，收到采用后再按快照导出。[评审操作](../skills/kara-previwer/SKILL.md)
